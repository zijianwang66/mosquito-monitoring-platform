# 蚊媒监测 Demo 实施计划

本轮目标是演示一条可复现的链路。模拟设备上报后，数据库完成校验和统计，页面能看到新读数、时段变化、地图点位和预警原因。

## 1. 固定联调环境与验收数据

- 在 PostgreSQL 创建 `mosquito_monitoring_test`，配置连接账号和密码文件。
- 运行 [start-demo.ps1](./start-demo.ps1)。它校验两天 CSV，初始化四层 schema，登记 7 台模拟设备，导入观测并检查 14 个点位日统计。
- 首次运行应新增 336 条观测。用同一文件再运行应新增 0 条。7 个点位每天均有 24 条有效样本。
- 固定页面演示日期为 2026-11-01 至 2026-11-02，打开 Demo 时默认选择这个区间。

**完成条件**　演示机按说明执行脚本即可恢复演示数据，并能查询 `app.point_daily_stats`。

## 2. 接通日统计 API 和第一张图

- 开一个只读接口，例如 `GET /api/demo/daily-stats?point=7&from=2026-11-01&to=2026-11-02`，查询应用层视图。
- 返回日期、指标、均值、中位数、有效样本数和缺测数。Demo 请求只取 `source_id='demo'` 且 `is_demo=true`。
- 驾驶舱先接入点位 7 的日图。图表增加均值与中位数切换，日期从接口返回值生成。
- 追加一条使用新时间戳的模拟观测，确认当天样本数和统计更新。重复导入同一批数据，数值保持一致。

**完成条件**　页面的两个日期、读数和样本数与数据库一致。零值显示 0，缺测留空，接口错误有提示。

## 3. 补时段统计和地图

- 在分析层增加小时统计，在应用层提供对应查询。按上海时间分小时，保留每小时最大单条蚊数和有效样本数。计算夜间趋势时明确起止日期，覆盖跨午夜时段。
- 统一设备总览、驾驶舱和地图的点位编号。现有布点图层有 1、2、4、5、6、7、8 号。为 Demo 的 3 号设置标记为模拟的坐标，补齐实际坐标时更新点位台账。
- 先让点位 3、7 可从图表定位。再把选中小时的读数接到现有 2 米网格估算，标明“模拟空间估算”。没有数据的点位显示缺测。

**完成条件**　切换到 14:00 或 21:00，3、7 号的读数超过 25。切换到 09:00，读数落在 10–20。地图和趋势对应同一时段。

## 4. 接上预警和居民提示

- 以“单条六类蚊数合计大于 25”作为 Demo 预警规则。用小时最大值判断该小时是否有记录触发，详情展示对应记录时间、点位和读数。
- 预警列表点击后定位到地图点位。居民页从同批发布结果读取区域及时段提示，显示模拟标记。
- 如需演示物业处置，再加一个可保存状态的巡查任务，演示从预警创建到完成。

**完成条件**　一次模拟上报能走到预警、地图定位与居民提示，重复导入不会重复产生同一条预警。

## 5. 现场走查后再扩充历史数据

- 走查统一入口、图表、地图、预警、零值、缺测以及重复导入。保留一小批增量文件做现场演示。
- 只演示数据闭环和按小时变化时，沿用现有两天数据。
- 要演示跨周趋势、日期筛选或周对比时，扩充到连续 14 天，共 2,352 条。保留现有两天原记录，从 11 月 3 日往后追加。
- 明确要求演示月报、11 月与 12 月整月对比或跨月查询时，才生成两个完整月。7 点位每小时一条，61 天共 10,248 条。12 月数据标明为模拟。
- 周、月中位数从该周期有效观测计算。周期均值也从有效观测汇总，避免日样本数不同时产生偏差。

厂商接口、真实仪器、正式预警规则及生产定时任务在试点接入时联调。Demo 可以通过本地模拟文件验证同一套清洗和入库逻辑。
